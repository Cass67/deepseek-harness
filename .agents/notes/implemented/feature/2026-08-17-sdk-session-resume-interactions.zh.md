# Agent Note：SDK 会话显式恢复，交互跨越 JSON-RPC

状态：已实现

[English](2026-08-17-sdk-session-resume-interactions.md) | 中文

## 问题

交互式 SDK 客户端需要发现持久化会话、读取精确历史、显式恢复、处理批准和用户问题。直接解析后端 JSONL 会把客户端绑定到一种持久化提供方。把未知提示词 ID 当作恢复会使创建语义含糊。批准与问题等待跨进程时还需要取消、首响应获胜的所有权和精确答案校验。

## 决策

JSON-RPC 协议增加 `session/list`、`session/history` 和 `session/resume`。列表与历史委托给 `ctx.sessionQuery`，由它负责实时优先的逻辑语料库和重放校验。历史读取绝不附加 agent。恢复通过独立的 `ctx.agents.resume` 操作完成；它重建最新记录的请求路由，安装与新 SDK 会话相同的模型选择机制，并进入 SDK 服务器现有的创建／关闭所有权映射。SDK 运行时不会组合已记录的 preset，因此会在发布 agent 前拒绝带 `agentPreset` 的持久化 header。

服务器在可选的 `ctx.userQuestions` 和批准服务各自处于活动状态时，注册为问题提供方和 `approval/request` 回答者。Cordis 依赖 fiber 会随服务生命周期变化添加、替换和移除这两项注册。每个待处理等待拥有一份克隆请求和一个随机请求 ID，然后发出 `interaction.requested`。客户端通过 `interaction/respond` 回答。服务器针对已发布的准确问题校验响应种类，以及问题 ID、顺序、选项标签、唯一性、自定义文本和单选／多选规则。服务器在结算前删除条目，因此首个有效响应获胜。中止、会话活动取消和服务器释放会结算待处理等待并尝试发出 `interaction.resolved`；请求通知失败会回滚发布，解决通知失败不能阻止结算。

TypeScript 与 Python 客户端公开对等的列表、历史、恢复、批准响应、问题响应和问题取消方法。每个具名响应都在客户端协议边界校验。历史校验覆盖持久化 header、连续事件 envelope 和 JSON 对象 payload，但不声称穷举扩展拥有的 payload 字段。默认 JSON-RPC 运行时组合包含会话查询精确读取、批准、用户问题和 ask-user 工具，且不会增加 stdout 输出；独立 minimal 运行时有意省略这些交互服务。

## 验证

服务器测试覆盖精确列表／历史委托、preset 安全恢复、批准关联、克隆问题所有权、可选服务生命周期变化、通知失败、重复响应、非法选项和结算。TypeScript 与 Python 测试覆盖非法历史和身份不匹配，组装快照覆盖完整的请求／响应／解决问题流程。

## 考虑过的替代方案

**由每个客户端解析 JSONL。** 这会排除 SQLite 与未来后端，并在所属服务之外重复会话修复和重放校验。

**把任何未知会话 ID 当作恢复。** 创建与恢复的失败和所有权语义不同；显式恢复可防止拼写错误静默创建空替代会话。

**使用服务端→客户端 JSON-RPC 请求。** 现有通知订阅已承载会话作用域异步工作；响应方法可提供首响应获胜校验，且无需为每个 SDK 增加第二个请求分派器。

## 后果

客户端无需了解持久化格式即可浏览和恢复会话。提示词／选择操作仍可惰性创建，而恢复保持显式且可审计。交互可承受传输延迟，但不会跨越运行时关闭；此进程自有 stdio 传输不提供重连重放，因此请求待处理期间调用方必须保持通知订阅活动。
